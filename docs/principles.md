# デザインの原則

Retrixは、メール、CRM、プロジェクト管理、文書、財務、チャットのような仕事の画面を組み立てるためのデザインシステムです。ゆとりのある大きさと余白、中央で仕事に向き合う構成、押す・選ぶ・片付ける操作が気持ちよく続くことを目指します。

## 骨格

- 画面は「上部中央のCommandMenu」と「中央の作業面」で作ります。画面端に固定するサイドバーは使いません。
- 作業面の左右には、開閉できる補助メニュー（Wing）を付けられます。常設のナビゲーションとは区別します。
- 狭い画面では左右の補助操作を別の行へ移し、中央の作業面を保ちます。

## 立体感と手触り

Retrixは「カード・パネル」と「ボタン」の区別で画面に奥行きを作ります。装飾的な模様やイラストは持たず、演出はアプリが意味と場所を決めて加えます。

- **立体感**：カードは影（`--rx-shadow-paper`、持ち上げたカードは`--rx-shadow-paper-lift`、浮かぶパネルは`--rx-shadow-menu`）で見せます。ボタンは縦の淡い陰影（`--rx-fill-control`）を持ち、主操作と「ここを見て」の面は役割の色の135度のグラデーションで塗ります。ボタンは普段は平らで、押すと内側へへこみます。
- **手触り**：出来事の瞬間にだけ短く動かします。確定・完了でペンが書くチェック、ドラッグで移動する項目の複製が持ち上がる影、元の場所に残る跡、挿入位置の線などです。常に動く飾りにはしません。
- **出入り**：浮かぶパネル（Dialog・Popover・HoverCard・Tooltip・Toast・DropdownMenu・CommandMenu・DatePicker）は、どこから来てどこへ戻るかを動きで示します。出入りの動きは`overlay.css`の一か所で定義し、各コンポーネントは支点（`transform-origin`）だけを決めます。支点から小さく現れて一瞬膨らんでから収まり、閉じる時は縮みながら速く消えます。Toastと画面の下に付くDialogは下から差し出し、Disclosureは高さを伸ばしながら中身を出します。

状態を示す線と模様は、装飾ではなく表示として使います。使えない枠の斜線、「これから」を示す破線、仮の予定、ドロップ先や空の列の細い破線、「今」を示す太枠です。

アプリが演出を加える時は、出来事の瞬間か、一画面に一つか二つの場所に置きます。一覧の全ての行や小さなコンポーネントに、同じ強さの飾りを付けません。

## 横断の規則

コンポーネントごとの都合で見た目を決めません。同じ意味には、どのコンポーネントでも同じ構造と同じディテールを使います。

### 形

同じ種類のコンポーネントは同じ形にします。角丸は次の段階だけを使い、コンポーネントごとの端数を作りません。

| 対象                                                                | 角丸                           |
| ------------------------------------------------------------------- | ------------------------------ |
| ボタン（Button・選択肢・ページ送りなど）                            | ピル（`--rx-radius-pill`）     |
| カード（作業面のCard・Boardの項目・Composer・メニュー・ダイアログ） | `--rx-radius-surface`（16px）  |
| 作業面の中の面（Navigationの背景、説明付きの選択肢など）            | `--rx-radius-field`（12px）    |
| 入力・選択の欄（Input・Select・InputGroup）、面の内側の行           | `--rx-radius-control`（8px）   |
| 小さな要素（チェックボックス・Keycap・Calendarの予定）              | `--rx-radius-mark`（4px）      |
| 作業面そのもの                                                      | `--rx-radius-sheet`（30px）    |
| 円                                                                  | アバター（Avatar）とマークだけ |

角丸と1pxの枠線を組み合わせた箱は作りません。Buttonは主・控えめ・危険の違いを塗りの色で出し、形では分けません。

### カードと情報と欄

- **カード・パネル**（手に取れる物・書く物・浮かぶ物）は枠線を持たず、影で見せます。
- **作業面に書かれた情報**は枠で囲みません。
  - 比べる行の一覧（DataList）と属性（ValueList）は、行の左右に余白を持たず、各行の下に淡い線を行の幅いっぱいに引きます。ホバーした行と今開いている行は、行いっぱいの淡い青の面で示します。
  - ツールへのショートカット（ActionList）は、地より淡い背景に塗りつぶしのアイコンと太字の名前の行を積みます。並べる時は淡い面のタイルにし、罫線と進む矢印は使いません。
  - 連絡の一覧（MessageList）は罫線を引かず行間で区切り、ホバーした行だけ角丸の淡い面にします。
  - TaskListは先頭と末尾の罫線と、行の間の淡い罫線を持ちます。
- **枠線を持つ**のは、入力・選択の欄と、意味のある線（Gridの罫など）だけです。欄は1pxの枠と内側の浅い影（`--rx-shadow-input`）で沈めます。フォーカスは青い縁の外に淡い青の輪（`--rx-focus-ring`）を広げ、Switch・チェックボックス・ラジオも同じ輪にします。
- 選択肢のグループ（ChoiceGroup）は枠で囲まず、Fieldと同じくラベルの下に並べます。

### グラデーション

用途は次の三つだけです。一覧・本文・情報の面は平らにします。

1. ボタンには、分かるか分からないかくらいの縦の陰影（`--rx-fill-control`）。
2. 「ここを見て」の面とマーク（主操作、Notice・ErrorSummaryの見出しのピル）には、役割の色からその淡い対への135度（`--rx-emphasis-*`、`--rx-fill-*`）。
3. Boardの項目は、列の色で先頭側の下の角から淡く染めて白へ戻す。

### 状態

- **現在地**はインクの太字と青いインジケーターで示します。横の並び（Tabsなど）は下に2pxのインジケーター、縦並びのNavigationは面を塗らず行の末尾に青いチェックを置きます。一覧の中で開いている行（DataList・MessageList）は淡い青の面と先頭側の2pxのインジケーターです。番号で並ぶ物（Pagination・Steps）だけは塗った円にします。パンくずの最後は太字だけにします。MessageListは太字を未読に使うため、現在地はインジケーターだけにします。
- **オン**（切り替えた状態）は青い塗りです。
- **選択中**（選んだ値）は淡い青の面です。
- 色だけで状態を伝えません。

### まとまりの見出し

太字の名前、件数、末尾側の操作の順に並べます。Section・Boardの列・目次・Comparison・FieldGroupで同じ形にします。続く一覧や表が罫線を持つので、見出しから線は伸ばしません。線を伸ばすのは、画面に一つの中央揃えのPageHeaderと、線そのものが役目のDividerだけです。Dividerの末尾に操作を置く時は、線を名前と操作の間だけに通し、操作は枠のない淡いピルにします。

### 項目の構造

一覧の項目は「題名（太字）・補足・メタ情報」の順にし、メタ情報は小さな文字を点で区切ります。状態のBadgeと操作は末端に寄せます。Card・DataList・ActionList・MessageList・Boardの項目で同じ順にします。選んだ候補のチップは、どの入力でも入力の下に置きます。

## 文字

| 役割                   | トークン             | 大きさ                                      |
| ---------------------- | -------------------- | ------------------------------------------- |
| 補足・日時             | `--rx-small`         | 12.5〜13px                                  |
| 操作・入力ラベル       | `--rx-label`         | 13.5〜14px、ラベルは600                     |
| 本文・一覧と項目の題名 | `--rx-body`          | 15〜16px、題名は600                         |
| 小見出し               | `--rx-section-title` | 20〜22px                                    |
| ページ見出し           | `--rx-title`         | 28〜36px                                    |
| Button・一行Input      | —                    | 高さ36px、largeは40px。タッチ操作は44px以上 |

大きさは画面幅に合わせて範囲の中で連続して変わります。文字に連動する値はrem・em・単位なしの行高で指定し、枠線の1pxを内寸へ二重に足しません。意味のない固定の高さで複数行を切りません。

UI全体は同じローカル書体の組み合わせを使い、字間はnormalにします。読む本文は行高と行の長さで読みやすさを作ります。全てを太字にせず、未読・現在地・見出し・入力や値の名前など、意味のある所に使います。同じ対象の題名と補足は近付け、行ごとに大見出しや長い説明を繰り返しません。

操作コンポーネントの文字は、枠の中で上下の中央に見えるよう専用のフォント定義（`--rx-control-font-family`）を使います。詳しくは[トークン](tokens.md#書体)を参照してください。

## 余白

- 目安の段は、補足4px、入力ラベル6px、関連要素8px、見出しと中身12px、異なる役割16px、まとまり24px、セクション32pxです。
- **間隔は余白より狭くします。** 器（カード・面・行・罫線で囲んだ段）の中の段の間は、器の内側の余白よりはっきり狭くします。比べるのは指定の数値ではなく、字形から字形までの見た目の距離です。数値が同じでも、段の間は行の余りが上下から加わって余白より広く見えます。目安は、間隔が余白の8割を超えないことです。
- 同じ種類の器は同じ余白にします（CardとLayerCardは上下20px・左右24px）。下端に操作が来る面も、段の間を詰めて差を作り、下の余白だけを締めません。
- 定型のCardやButtonは上下より左右に少し広い余白を取ります。作業面（Surface）は上下を同じ余白（32px）にし、中の段の間を16pxに詰めます。

## 色

- 青は主操作とリンク、緑・アンバー・コーラルは明示した分類や状態に使います。業務名や人物名から色を自動で割り当てません。
- 蛍光ペンの黄（`--rx-mark`）は「今日」のマーカーと、文中の一致した語の強調（`mark`）だけに使います。
- 操作のメニュー（DropdownMenu・FilterMenu）は青の面（`--rx-fill-menu`）に白い文字で出します。見落とされてはいけないToastも、通知の種類の色（情報は青、成功は緑、注意はアンバー、失敗は赤）で塗ります。読み物や入力を載せるDialog・Popover・HoverCardは白いパネルにします。

## リンク

リンクに下線を引きません。行ごと押せる濃い色の文字か、ピルにします。文字だけの操作（Buttonのlink）は青い文字にし、ホバーすると淡い青のピルの面を出します。一覧の題名はホバー時に青くします。文章（段落・引用・図の説明）の中に混ざるリンクだけは、色だけに頼らないよう細く淡い下線を残します。

## 配置

- Gridは列の対応があるところ（項目名と値、人物と本文、日付と内容）に使います。縮む列は`minmax(0, 1fr)`にします。
- Flexは内容の自然幅で並べるところ（操作群、分類名、件数）に使います。短い補足を端まで押し離すためだけに`space-between`を使いません。
- 文章は通常のblockで流します。段落や補足の関係には`margin-block-start`、同列の子の間隔は親の`gap`を使います。
- 入力・ボタンの内側はコンポーネント自身が持ち、親は外側の配置だけを持ちます。
- Container queryはコンポーネントの利用可能な幅で判断します。表と月のカレンダーは列の関係を保ったまま領域内でスクロールします。
- 面に付く操作は縁をまたがせます（Carouselの前後、Comparisonの矢印、Noticeの見出し）。位置はButtonではなく包む要素が持ちます。

## 役割の分担

- CommandMenuはアプリ全体の移動と操作、DropdownMenuは対象に対する操作、Dialogは判断が必要な処理、Popoverは対象の近くの補足です。全体の移動をDropdownMenuへ押し込みません。
- Fieldは名前・説明・エラーを入力へ関連付けます。数値・日付・時刻の送信値と、表示上の補助は分けます。
- 継続して読む案内はNotice、修正先の一覧はErrorSummary、何もない理由はEmptyState、測れる進み具合はProgress、待機はLoading、結果の通知はToastにします。
- 業務データ・権限・通信・永続化は利用するアプリが持ちます。Retrixは情報の読み順・配置・操作を共通化します。
