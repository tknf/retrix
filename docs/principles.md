# デザインの原則

Retrixは、マスタ管理・顧客管理・案件管理・設定のような業務の画面を組み立てるためのデザインシステムです。手本は2012年前後の37signalsの画面（Basecamp 2・Highrise）です。机の上に白い紙を置き、その紙に表や一覧や文章を書き込むような見た目で、情報を多く並べても読み順が崩れないことを目指します。

表を中心にした一覧・詳細・編集の画面が最も得意です。ただし、それ以外の画面（文書、予定、連絡、ボード）も同じ作法で組めます。

## 画面構成

- 画面は「机」と「シート」で作ります。地はクリーム色の机（`--rx-background`）で、その上の中央に白いシート（作業面）を一枚置きます。画面の幅いっぱいには広げません。
- ヘッダーはシートと同じ幅に揃え、アプリの名前、主な移動先、検索を一行に並べます。背景を持たず、机の上にそのまま置きます。アカウントへのリンクは、その上の行の末尾側に小さく置きます。
- 上の階層は、シートの背後に重ねた淡い灰色のシート（`AppShell`の`trail`）で示します。背後のシートの見出しは上の階層へのリンクです。
- 分類ごとの移動先や最近見た項目は、シートの先頭側の列（`AppShell`の`aside`）に置けます。列はシートの外の机の上に置き、列とシートを合わせて中央に揃えます。画面の端に固定するサイドバーにはしません。
- シートの中で補足（担当者、関係者、操作のリンク）を並べる時は、本文の右側に細い列を作ります（`SplitView`・`.rx-workspace`）。

## 紙と線

Retrixは「白い紙」「罫線」「枠のある欄とボタン」で画面を作ります。影は紙を机に置いた分だけの浅いものにし、浮かせる演出には使いません。

- **シートとカード**は、1pxの輪郭と浅い影を持つ白い紙です（`--rx-shadow-sheet`・`--rx-shadow-paper`）。輪郭は影の一つ目で描くので、コンポーネントは枠線を別に引きません。
- **浮かぶパネル**（Dialog・Popover・DropdownMenu・Toastなど）は、輪郭と、カードより少し遠くまで落ちる影（`--rx-shadow-menu`）を持つ白いパネルです。
- **罫線**は黄みを帯びた淡い灰色（`--rx-border`）の1pxです。一覧と表の行は、行の幅いっぱいに罫線を引いて区切ります。
- **欄とボタン**は枠を持ちます。枠は罫線より濃い灰色（`--rx-control-border`）で、欄は上の枠を、ボタンは下の枠を少し濃くして、沈んだ欄と置かれたボタンを見分けやすくします。
- 状態を示す線と模様は表示として使います。使えない枠の斜線（`--rx-hatch`）、「これから」の破線、「今」の太枠です。

## 形

角は小さくします。丸いのは、件数やメタ情報のピルとアバターだけです。

| 対象                                                   | 角丸                           |
| ------------------------------------------------------ | ------------------------------ |
| ボタン・入力欄・選択の欄                               | `--rx-radius-control`（3px）   |
| カード・パネル（Card・メニュー・ダイアログ・Toast）    | `--rx-radius-surface`（4px）   |
| シートの中の枠（説明付きの選択肢・ナビゲーションなど） | `--rx-radius-field`（4px）     |
| 小さな要素（チェックボックス・Keycap・予定）           | `--rx-radius-mark`（2px）      |
| シート                                                 | `--rx-radius-sheet`（3px）     |
| 件数・担当者・日付のピル、Tag、Badge                   | ピル（`--rx-radius-pill`）     |
| 円                                                     | アバター（Avatar）とマークだけ |

## 色

色は少なく、意味を決めて使います。

| 役割             | トークン                  | 使い方                                              |
| ---------------- | ------------------------- | --------------------------------------------------- |
| 机の地           | `--rx-background`         | 画面の地。クリーム色                                |
| 紙               | `--rx-surface`            | シート・カード・パネル・欄                          |
| 本文             | `--rx-text`・`--rx-ink`   | 本文と、題名・現在地の黒                            |
| 補足             | `--rx-muted`              | 説明・抜粋・ラベルの灰色                            |
| 日付・投稿者     | `--rx-meta`               | 「9月25日に投稿」のような補足の茶色                 |
| リンク           | `--rx-link`               | 青緑の文字と下線。ホバーで赤茶（`--rx-link-hover`） |
| まとまりの見出し | `--rx-heading`            | Sectionなどの見出しの赤茶                           |
| 主操作           | `--rx-fill-primary`       | 緑のボタン。一つの画面に一つか二つ                  |
| 危険             | `--rx-danger`             | 削除などの赤茶                                      |
| 選んでいる状態   | `--rx-teal`・`--rx-cover` | オンのボタンの青緑の塗り、選んだ行の淡い青緑        |
| 黄色のハイライト | `--rx-mark`               | 今日、選んだ行、更新した行、文中の一致した語        |
| 件数のピル       | `--rx-info-soft`          | コメント数などの淡い青のピル                        |
| 黄色の紙         | `--rx-note`               | テキスト文書やメモのカード                          |

- 業務名や人物名から色を自動で割り当てません。分類の色（`--rx-green`・`--rx-amber`・`--rx-coral`など）は、利用側が明示した時だけ使います。
- 白地の文字は4.5:1以上のコントラストを保ちます。色だけで状態を伝えません。

## グラデーション

用途は次の三つだけです。一覧・本文・情報の面は平らにします。

1. ボタンの手触り（`--rx-fill-control`）：白から淡い灰色への縦の塗り。
2. 主操作・危険・オンの塗り（`--rx-fill-primary`・`--rx-fill-danger`）：役割の色の縦の塗り。
3. 「ここを見て」の面（`--rx-emphasis-*`）：ごく淡い縦の塗り。Noticeの見出しなど。

## 文字

| 役割                 | トークン             | 大きさ                 |
| -------------------- | -------------------- | ---------------------- |
| 補足・日時           | `--rx-small`         | 12px                   |
| 操作・入力ラベル     | `--rx-label`         | 13px、ラベルは600      |
| 本文・一覧と表の題名 | `--rx-body`          | 14px、題名は600        |
| まとまりの見出し     | `--rx-section-title` | 18px、赤茶、通常の太さ |
| ページ見出し         | `--rx-title`         | 24〜28px、太字の黒     |
| Button・一行Input    | —                    | 高さ30px、largeは36px  |

- まとまりの見出し（Section）は、赤茶の通常の太さの文字にし、その後ろに小さなボタンを並べます（「議論　［新しい投稿］」）。
- 列やまとまりの小見出し（表の見出し、サイドの列の見出し）は、小さな太字か、字間を空けた大文字にします。
- 操作コンポーネントの文字は、枠の中で上下の中央に見えるよう専用のフォント定義（`--rx-control-font-family`）を使います。詳しくは[トークン](tokens.md#書体)を参照してください。

## リンクと操作

- リンクは青緑の文字に下線を引きます。ホバーすると赤茶になります。押せる文字であることを、色と下線の両方で示します。
- ヘッダーの移動先、表の列見出しの並べ替え、ピルなど、コンポーネントが持つリンクは、それぞれのコンポーネントが見た目を決めます。
- 文字だけの操作（Buttonの`link`）もリンクと同じ見た目にします。
- 操作のリンクを本文の右側に縦に並べる時は、項目の間に罫線を引きます（「編集」「削除…」）。

## 状態

- **現在地**は黒い太字で示します。横の並び（Tabs）は選んだタブを紙の色にしてつなげ、縦の並び（Navigation）は行を淡い面で塗ります。
- **オン**（切り替えた状態）は青緑の塗りです。
- **選択中**（選んだ値・選んだ行）は黄色のハイライト（`--rx-mark`）か淡い青緑（`--rx-cover`）の面です。表と一覧で選んだ行は黄色にします。
- **更新した直後**の行は、黄色のハイライトを一度だけ出して消します（`--rx-duration-flash`）。
- 色だけで状態を伝えません。

## まとまりの見出し

見出し、件数、操作の順に並べます。Section・Boardの列・目次・FieldGroupで同じ形にします。見出しから線は伸ばしません。線を伸ばすのは、PageHeaderの下と、線そのものが役目のDividerだけです。

## 項目の構造

一覧の項目は「題名（リンク）・抜粋・メタ情報」の順にし、メタ情報は小さな茶色の文字を点で区切ります。件数は淡い青のピル、担当者と期日は灰色のピルにします。状態のBadgeと操作は末端に寄せます。

## 余白

- 目安の段は、補足4px、入力ラベル6px、関連要素8px、見出しと中身12px、異なる役割16px、まとまり24px、セクション32pxです。
- 情報を多く並べる画面のため、余白はPlyより詰めます。シートの内側の余白は32px、カードは上下16px・左右20pxです。
- **間隔は余白より狭くします。** 器（カード・面・行・罫線で囲んだ段）の中の段の間は、器の内側の余白よりはっきり狭くします。

## 配置

- Gridは列の対応があるところ（項目名と値、人物と本文、日付と内容）に使います。縮む列は`minmax(0, 1fr)`にします。
- Flexは内容の自然幅で並べるところ（操作群、分類名、件数）に使います。
- 文章は通常のblockで流します。段落や補足の関係には`margin-block-start`、同列の子の間隔は親の`gap`を使います。
- 入力・ボタンの内側はコンポーネント自身が持ち、親は外側の配置だけを持ちます。
- Container queryはコンポーネントの利用可能な幅で判断します。表と月のカレンダーは列の関係を保ったまま領域内でスクロールします。

## 動き

動きは控えめにします。出来事の瞬間（確定のチェック、更新した行の黄色のハイライト、パネルの出入り）だけに短く使い、常に動く飾りにはしません。浮かぶパネルの出入りは`overlay.css`の一か所で定義し、各コンポーネントは支点（`transform-origin`）だけを決めます。

## 役割の分担

- AppShellのヘッダーはアプリ全体の移動、CommandMenuは名前で探す移動と操作、DropdownMenuは対象に対する操作、Dialogは判断が必要な処理、Popoverは対象の近くの補足です。
- Fieldは名前・説明・エラーを入力へ関連付けます。数値・日付・時刻の送信値と、表示上の補助は分けます。
- 継続して読む案内はNotice、修正先の一覧はErrorSummary、何もない理由はEmptyState、測れる進み具合はProgress、待機はLoading、結果の通知はToastにします。
- 業務データ・権限・通信・永続化は利用するアプリが持ちます。Retrixは情報の読み順・配置・操作を共通化します。
